# Descriptors and the Descriptor Protocol

Descriptors are a powerful but often overlooked feature of Python that underlies many of the language's built-in mechanisms, including `property`, `classmethod`, `staticmethod`, and `staticmethod`. A descriptor is any object that implements the **descriptor protocol** — special methods that Python calls when an attribute is accessed, set, or deleted.

## What Descriptors Are

A descriptor is an object that is assigned to a class attribute. When you access, set, or delete that attribute on an instance, Python does not directly return the object — instead, it calls one of the descriptor's special methods. This allows you to intercept and control attribute access at the language level.

```python
class Descriptor:
    def __get__(self, obj, objtype=None):
        return f"Getting value: {obj._value if obj else 'no instance'}"

    def __set__(self, obj, value):
        obj._value = value

    def __delete__(self, obj):
        del obj._value

class MyClass:
    attribute = Descriptor()

    def __init__(self, value):
        self._value = value

obj = MyClass(42)
print(obj.attribute)   # Getting value: 42
obj.attribute = 100
print(obj.attribute)   # Getting value: 100
del obj.attribute      # Deletes obj._value
```

When `obj.attribute` is accessed, Python recognizes that `attribute` is a descriptor object and calls its `__get__` method. When you assign to `obj.attribute`, Python calls `__set__`. When you delete it, Python calls `__delete__`.

## __get__, __set__, __delete__ Protocol

The descriptor protocol consists of three methods:

- `__get__(self, obj, objtype=None)` — Called when the attribute is read. Must return the attribute value.
- `__set__(self, obj, value)` — Called when the attribute is assigned. Must store the value.
- `__delete__(self, obj)` — Called when the attribute is deleted with `del`.

Any object that implements at least one of these methods is a descriptor. An object that implements only `__get__` is a **non-data descriptor**; an object that implements `__set__` or `__delete__` (or both) is a **data descriptor**.

```python
class ValidatedInteger:
    def __init__(self, min_value=None, max_value=None):
        self.min_value = min_value
        self.max_value = max_value

    def __set_name__(self, owner, name):
        self.name = name  # The name of the attribute being validated

    def __get__(self, obj, objtype=None):
        if obj is None:
            return self  # Accessing from class, not instance
        return obj.__dict__.get(self.name, 0)

    def __set__(self, obj, value):
        if not isinstance(value, int):
            raise TypeError(f"{self.name} must be an integer")
        if self.min_value is not None and value < self.min_value:
            raise ValueError(f"{self.name} must be >= {self.min_value}")
        if self.max_value is not None and value > self.max_value:
            raise ValueError(f"{self.name} must be <= {self.max_value}")
        obj.__dict__[self.name] = value

class Person:
    age = ValidatedInteger(min_value=0, max_value=150)
    score = ValidatedInteger(min_value=0, max_value=100)

person = Person()
person.age = 30
person.score = 95

print(person.age)   # 30

person.age = -5     # Raises ValueError: age must be >= 0
person.score = 200  # Raises ValueError: score must be <= 100
person.age = "old"  # Raises TypeError: age must be an integer
```

The `__set_name__(self, owner, name)` method is called automatically when the descriptor is assigned to a class attribute. It receives the owner class and the attribute name, which is useful for validation and naming.

## Data vs Non-Data Descriptors

The distinction between data and non-data descriptors affects attribute lookup precedence. Python's attribute lookup order is:

1. Data descriptors (defined in the class)
2. Instance `__dict__`
3. Non-data descriptors (defined in the class)
4. Class attributes (including other descriptors)

Because data descriptors are checked before the instance dictionary, they take precedence over instance attributes. This is why `property` (which is a data descriptor) can intercept attribute assignment to instance attributes:

```python
class Counter:
    def __init__(self):
        self._count = 0

    @property
    def count(self):
        return self._count

    @count.setter
    def count(self, value):
        if value < 0:
            raise ValueError("Count cannot be negative")
        self._count = value

c = Counter()
c.count = 10
print(c.count)     # 10

# Direct instance attribute access still works for non-descriptor attrs
c._count = 5
print(c.count)     # Still 10 because count is a data descriptor
```

Since `property` is a data descriptor, assigning to `c.count` calls the setter rather than creating a new instance attribute. The instance dictionary is bypassed for data descriptors during assignment.

## Properties as Descriptors (Revisited)

Properties are the most common example of descriptors in everyday Python. The `@property` decorator creates a property object, which is a data descriptor that implements `__get__` and `__set__`:

```python
class Example:
    @property
    def value(self):
        return self._value

# This is equivalent to:
class Example:
    def getter(self):
        return self._value

    value = property(getter)  # property is a descriptor
```

You can also use the property descriptor's setter and deleter methods to chain additional behavior:

```python
class Temperature:
    def __init__(self, celsius):
        self._celsius = celsius

    @property
    def celsius(self):
        return self._celsius

    @celsius.setter
    def celsius(self, value):
        self._celsius = value

    @property
    def fahrenheit(self):
        return self._celsius * 9/5 + 32

    @fahrenheit.setter
    def fahrenheit(self, value):
        self._celsius = (value - 32) * 5/9
```

Both `celsius` and `fahrenheit` are property descriptors. Setting one updates the internal state, and getting the other computes the converted value.

## Custom Descriptor Examples

### Lazy Property Descriptor

A descriptor that computes a value only when first accessed and then caches it:

```python
class LazyProperty:
    def __init__(self, func):
        self.func = func
        self.name = func.__name__

    def __set_name__(self, owner, name):
        self.name = name

    def __get__(self, obj, objtype=None):
        if obj is None:
            return self

        value = self.func(obj)
        # Cache the value in the instance's __dict__
        obj.__dict__[self.name] = value
        return value

    def __set__(self, obj, value):
        raise AttributeError(f"Cannot set {self.name} — use setter method instead")

class ExpensiveComputation:
    def __init__(self, data):
        self._data = data

    @LazyProperty
    def result(self):
        print("Computing result (expensive)...")
        return sum(self._data) / len(self._data)

obj = ExpensiveComputation([1, 2, 3, 4, 5])
print("Object created")

# The first access triggers computation
print(obj.result)  # Computing result (expensive)... 3.0

# Subsequent accesses return cached value
print(obj.result)  # 3.0 (no print message — cached)
```

### Self-Managing Descriptor with Weakref Cache

```python
import weakref

class CachedCalculation:
    """Descriptor that caches results based on input arguments."""
    def __init__(self, func):
        self.func = func
        self.cache = weakref.WeakValueDictionary()

    def __set_name__(self, owner, name):
        self.name = name

    def __get__(self, obj, objtype=None):
        if obj is None:
            return self

        # Create a cache key from the instance's id and any arguments
        def calculate(*args):
            key = (id(obj), args)
            if key not in self.cache:
                self.cache[key] = self.func(obj, *args)
            return self.cache[key]

        return calculate
```

## Hands-On Exercise

Create a `Replicated` descriptor that replicates the assigned value across multiple attribute names. When you assign to a `Replicated` field, it updates not just the primary attribute but also one or more replica attributes on the same object.

For example:

```python
class User:
    name = Replicated('display_name', 'login_name')  # Replicates to display_name and login_name
    email = Replicated('contact_email')
```

When you set `user.name = "Alice"`, the descriptor should set `user.display_name = "Alice"` and `user.login_name = "Alice"` as well. Implement `__set_name__` to receive the primary attribute name, and implement `__set__` to write the value to all replicated attributes.

```python
class Replicated:
    def __init__(self, *replica_names):
        self.replica_names = replica_names
        self.primary_name = None

    def __set_name__(self, owner, name):
        self.primary_name = name

    def __get__(self, obj, objtype=None):
        if obj is None:
            return self
        return obj.__dict__.get(self.primary_name, None)

    def __set__(self, obj, value):
        # Set primary attribute
        obj.__dict__[self.primary_name] = value
        # Set all replica attributes
        for name in self.replica_names:
            obj.__dict__[name] = value

    def __delete__(self, obj):
        del obj.__dict__[self.primary_name]
        for name in self.replica_names:
            if name in obj.__dict__:
                del obj.__dict__[name]
```

Descriptors are one of the most advanced and powerful features in Python, forming the foundation for properties, bound methods, class methods, and many other language constructs. Understanding them unlocks a deeper comprehension of how Python works internally.
