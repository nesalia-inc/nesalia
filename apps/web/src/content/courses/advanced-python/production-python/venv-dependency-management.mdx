# Virtual Environments and Dependency Management

Python applications have dependencies: external packages that provide functionality beyond the standard library. Managing these dependencies is critical because different projects need different package versions, and those versions can conflict. A **virtual environment** is an isolated Python environment that contains its own installation of Python and packages, allowing each project to have exactly the dependencies it needs without conflicts.

## Why Virtual Environments Matter

Without virtual environments, all packages install into the system Python, meaning one project might require `requests==2.28.0` while another needs `requests==2.31.0`. These conflicts make it impossible to run both projects on the same system. Virtual environments solve this by giving each project its own isolated space.

## Creating a Virtual Environment

Python's built-in `venv` module creates virtual environments:

```bash
# Create a new virtual environment
python -m venv .venv

# Activate it (Linux/macOS)
source .venv/bin/activate

# Activate it (Windows Command Prompt)
.venv\Scripts\activate.bat

# Activate it (Windows PowerShell)
.venv\Scripts\Activate.ps1
```

After activation, your prompt changes to show `(.venv)`, indicating you are working inside the virtual environment. Running `python` now uses the virtual environment's Python interpreter, and `pip` installs packages into the virtual environment rather than the system Python.

## Installing and Managing Dependencies

Use `pip` to install packages into the active virtual environment:

```bash
# Install specific packages
pip install requests==2.31.0
pip install flask==3.0.0

# Install from requirements file
pip install -r requirements.txt

# List installed packages
pip list

# Generate requirements file
pip freeze > requirements.txt
```

The `pip freeze` command outputs all installed packages in a format suitable for requirements files. However, `pip freeze` includes every package including transitive dependencies, which can be noisy.

## Using pip-tools for Better Dependency Management

The `pip-tools` package provides more control over dependencies. It separates direct dependencies from transitive ones:

```bash
# Install pip-tools
pip install pip-tools
```

Create a `requirements.in` file listing only your direct dependencies:

```
requests>=2.31.0
flask>=3.0.0
python-dotenv>=1.0.0
```

Then compile it to generate a `requirements.txt` with pinned versions:

```bash
# Generate requirements.txt with all dependencies resolved
pip-compile requirements.in
```

The generated `requirements.txt` includes every package with exact versions:

```
#
# This file is autogenerated by pip-compile
#
# It does not update the pip installation
# Run "pip install -r requirements.txt" to install
#
click==8.1.7
flask==3.0.0
idna==3.6
requests==2.31.0
urllib3==2.1.0
werkzeug==3.0.1
```

This approach ensures reproducible builds because every package version is locked.

## Reinstalling Dependencies from Requirements

When working in a new environment or after deleting a virtual environment, reinstall from requirements:

```bash
# After creating a new venv
pip install -r requirements.txt
```

This installs exactly the packages and versions specified in `requirements.txt`, ensuring consistency across environments.

## Organizing Requirements Files

Large projects often split requirements into multiple files for different environments:

```
# requirements.txt - core production dependencies
-r requirements.txt

# requirements-dev.txt - development-only tools
-r requirements.txt
pytest>=7.4.0
black>=23.0.0
mypy>=1.7.0
```

In your development environment:

```bash
# Install all dependencies including dev tools
pip install -r requirements-dev.txt
```

In production:

```bash
# Install only production dependencies
pip install -r requirements.txt
```

This separation keeps production environments lean while providing all tools needed for development.

## Upgrading Dependencies

Keeping dependencies updated is important for security and features. Use `pip-compile` with the `--upgrade` flag:

```bash
# Upgrade all packages to latest compatible versions
pip-compile --upgrade requirements.in
```

Then in your virtual environment:

```bash
pip install -r requirements.txt
```

For a safer approach, upgrade packages one at a time and run tests to ensure nothing breaks.

## Handling Version Conflicts

When packages require conflicting versions of the same dependency, pip reports the conflict:

```bash
pip install requests==2.28.0 httpx==0.25.0
```

Output:

```
ERROR: ResolutionImpossible
  Looking in indexes: https://pypi.org/simple/
  Because package A depends on urllib3>=1.0
  And package B depends on urllib3<1.0, these requirements are incompatible.
```

To resolve conflicts, try using different package versions or find alternative packages that have compatible dependencies. Tools like `pip-compile` often find compatible versions that `pip install` misses.

## The pyproject.toml Modern Standard

The Python community has moved toward `pyproject.toml` as the standard for project configuration. This format supports modern build systems:

```toml
# pyproject.toml
[project]
name = "my-app"
version = "1.0.0"
description = "A production Python application"
requires-python = ">=3.10"
dependencies = [
    "requests>=2.31.0",
    "flask>=3.0.0",
    "python-dotenv>=1.0.0",
]

[project.optional-dependencies]
dev = [
    "pytest>=7.4.0",
    "black>=23.0.0",
    "mypy>=1.7.0",
]

[build-system]
requires = ["setuptools>=61.0"]
build-backend = "setuptools.build_meta"
```

Install dependencies with:

```bash
# Install base dependencies
pip install -e .

# Install with development tools
pip install -e ".[dev]"
```

Using `pip install -e .` (editable install) installs the package in development mode, linking it to the source directory so changes take effect immediately without reinstallation.

## Best Practices for Dependency Management

- **Always use a virtual environment** — Never install packages globally except for system tools
- **Pin versions in production** — Use `requirements.txt` with exact versions for reproducible builds
- **Separate dev and production dependencies** — Keep testing and development tools out of production
- **Review dependency changes** — Check what changed in `requirements.txt` during code reviews
- **Update regularly** — Run `pip-compile --upgrade` periodically to get security fixes

## Summary

- Virtual environments isolate project dependencies to prevent conflicts
- Create a virtual environment with `python -m venv .venv` and activate it before work
- Use `requirements.in` for direct dependencies and `pip-compile` to generate locked requirements
- Separate development and production requirements files for lean production deployments
- Modern projects use `pyproject.toml` for standardized configuration
- Keep dependencies updated and review changes during code review
